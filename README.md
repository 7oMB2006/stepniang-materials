# 阶跃娘素材站 · 审核仓库

**投稿暂未开放。** 这是非官方社区项目。目前只准备审核基础设施，不发布网站，不接收真实申请。

站点仍在开发，本仓库仅同步审核所需的最小索引，不包含现有图片、作者完整资料或整站源码。
当前登记 1 位作者、65 件日常素材，其中 2 件保留未署名；不据此补齐归属或许可。

## 本阶段有什么

- `requests/`：预留申请目录，现在保持为空。
- `.github/`：PR 模板、维护者署名规则和自动检查。
- `config/intake.json`：入口开关，当前为 `open: false`。
- `registry/`：经维护者确认的作者 ID、GitHub 数字账号 ID 及作品署名索引；不包含邮箱、简介、链接、头像或原图。
- `validation/` 与 `shared/`：当前表单 v1/v2/v3 的校验协议快照，不是已定稿的站点源码。
- `scripts/` 与 `tests/`：只读校验工具和合成数据测试，不执行作者提交的脚本。

## 将来的申请流程

正式开放后，在站内填写并导出 ZIP，将解压后的文件放入一个新的
`requests/<申请编号>/` 目录，再发起 PR。不是把 ZIP 当作唯一文件上传。
每个 PR 只处理一份申请，不直接修改正式作者、作品资料、已有申请或工具代码。

```text
requests/<申请编号>/
  submission.json
  PR.md
  files/             # 只在有新附件时存在
```

支持投稿作品、仅修改作者资料、申请撤下作品。仅改文字或申请撤下无需重传作品原件。
包格式、审核规则、身份核对和重新导入沿用表单协议，细节见 [审核说明](CONTRIBUTING.md)。
**现在请不要按此流程提交真实申请。**

## 自动检查的边界

`Repository checks` 检查受信任分支上的工具、测试和配置。
`Request gate` 使用 PR 基准分支的规则读取申请文件，不检出或运行 PR 里的代码。
入口关闭时，新增或修改 `requests/` 的 PR 会失败；修改开关和提交申请不能混在同一个 PR 中绕过关闭状态。

自动检查不会合并 PR、绑定账号、收录作品、部署网站或删除图片。
公开仓库本身仍允许别人创建 PR；“未开放”由说明和校验体现，不代表 GitHub 禁止创建 PR。
CODEOWNERS 只声明维护责任，不等于已启用分支保护。
main 已另行配置必需的 `Request gate`、人工审核以及禁止强推和删除规则；
维护者的 PR 内人工审核豁免不跳过必需检查。配置规则不代表投稿已开放。

索引中的数字账号绑定由维护者核实后登记，不能由申请人自行填写生效。
未署名作品的 `authorIds` 保持为空，不允许凭账号或来源说明自行认领。
索引同步不修改站点资料、不上传或撤下图片，也不打开入口。

## 本地验证

使用 Node.js 24.15.0：

```sh
npm ci --ignore-scripts
npm test
npm run check
```

不会读取本机素材目录或访问网站运行数据。测试图片在内存生成，临时 Git 仓库只写入系统临时目录并在测试后清理。

### 同步协议快照

`validation/snapshot.json` 记录四个白名单模块的 SHA-256，文本统一为 LF，
避免 Windows 与 Linux 换行造成校验漂移。不会自动读取作者、作品或站点配置。
维护者在确认站内协议改动后手动运行，再逐项审查差异并测试：

```sh
node scripts/sync-validation.mjs --from <本地站点目录>
npm test
npm run check
```

入口、索引或协议正式调整时，也需更新测试中的本阶段关闭状态与索引断言；不能只改开关跳过验收。

## 开放前

1. 完成剩余站点功能，核对导出格式与这份协议快照。
2. 经维护者确认后同步最小索引，不自动上传姓名、邮箱、简介或原件。
3. 完成 GitHub 真实账号归属核对；已有作者的数字账号绑定不能由申请人自己填写生效。
4. 配置并验证分支保护、所需检查和人工审核流程。
5. 在测试 PR 中验收成功、失败、更新申请与撤下流程。
6. 更新站内引导与提交目录说明，再单独把 `open` 改为 `true`。
